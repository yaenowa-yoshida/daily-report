# 日報入力ツール

15分ごとに「これからやる作業」を尋ね、案件・作業内容をCSVに積み上げていく常駐ツール。
一日の終わりに表で確認して締めると、月次報告書へ転記できる形の記録が残る。

**使い方は `ユーザーマニュアル.xlsx` を参照。** このREADMEは構成と保守のためのメモ。

- 記録の単位: 15分（CSVの1行 = 15分枠）
- 出力: `日報ログ\日報ログ_YYYY-MM-DD.csv`（1日1ファイル、UTF-8 BOM、列は 日付,時刻,案件,作業内容）
- 動作環境: Windows + Windows PowerShell 5.1（追加インストール不要・通信なし・すべてローカル完結）

## ファイル構成

```
日報記録\
  ユーザーマニュアル.xlsx      … 利用者向けの使い方（配布物）
  ユーザーマニュアル生成.ps1   … 上のxlsxを作り直すスクリプト。本文はこちらが持つ
  README.md                    … このファイル（構成・保守メモ）
  CLAUDE.md                    … このフォルダを触るときのルール
  Nippo-Batch.ps1              … プログラム本体（1ファイル）
  日報入力.bat                 … 起動用。デスクトップのショートカットの実体
  日報システム紹介プレゼン.html … 紹介スライド（全24枚。矢印キーで送る）
  画像\                        … マニュアル・プレゼンに貼る画面のスクリーンショット
  日報ログ\                    … 出力（1日1CSV。初回の記録時に作られる）
  日報設定\                    … 案件.txt / 作業名.txt
  .claude\settings.json        … Claude Code の許可設定
```

`日報設定` は初回起動時に雛形が自動生成される。
ログ・設定はどちらも **`Nippo-Batch.ps1` と同じフォルダ**を基準に解決している（`$reportDir = $PSScriptRoot`）ため、フォルダごと移動しても動く。

マニュアルの本文は `ユーザーマニュアル生成.ps1` が持っている。内容を直すときはこのスクリプトを編集して実行する（Excelが必要。既存のxlsxは上書きされる）:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 日報記録\ユーザーマニュアル生成.ps1
```

### 画面のスクリーンショット

マニュアルとプレゼンに貼っている画面画像は、アプリ本体から自動で撮れる。**UIを変えたらこれを実行するだけで資料の画像が最新になる。**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 日報記録\Nippo-Batch.ps1 -Capture
```

`画像\` に6枚（入力ウィンドウ・日報メニュー・休憩中・MTG予約・一覧編集・選択肢の編集）を書き出す。プレゼンHTMLは相対パスで参照しているので撮り直せば即反映、マニュアルは再生成が必要。

- **中身はダミー値**（案件A／PRJ-12 商品ページ改修 など）。実際の案件名・チケット名が資料に出ないよう、設定ファイルは読まずスクリプト内の `$SHOT_PROJECTS` / `$SHOT_TASKS` を使う。値を変えたいときはここを編集する。
- 撮影中は画面にウィンドウと無地の背景が一瞬表示される（画面に出ていないと中身を撮れないため）。数秒で終わる。
- 無地の背景を敷いているのは、Windows 11 の丸角からデスクトップが写り込むのを防ぐため。

## 起動の仕組み

- 利用者が**デスクトップの「日報入力」ショートカットを毎朝ダブルクリック**して起動する → `日報入力.bat` → `powershell.exe -WindowStyle Hidden -File Nippo-Batch.ps1`
- 起動時、デスクトップに「日報入力」ショートカットが無ければ自動生成し、作成したことをメッセージで通知する（`Initialize-DesktopShortcut`）
- 二重起動はミューテックス（`Local\NippoBatchMutex`）で防止。プロセスは「業務終了 → 締め」でのみ終了する

> **自動起動（スタートアップ登録）とexe化は、どちらも採用しない。**
> どちらも一度実装したが、組織のポリシーで使えなかった（exeは生成物の実行がブロックされて削除され、スタートアップ登録も運用ルール上使えない）。
> **PC起動時の自動起動は存在しない**ので、ドキュメントにその前提を書かないこと。デスクトップのショートカットが唯一の起動口であり、
> それが消えると起動手段を見失うため、起動のたびに作り直す仕様にしている。

## 変更のしかた

`Nippo-Batch.ps1` を編集して保存すれば、次回起動から反映される（ビルド作業は不要）。
スクリプト冒頭のコメントに、以下16セクションの構成と記録の考え方を書いてある。

| # | セクション | 内容 |
|---|---|---|
| 1 | 定数とパス | ファイル位置、15分という単位、書式の定義 |
| 2 | 共通ユーティリティ | 枠の計算、CSV行の組み立て、メッセージ表示 |
| 3 | 設定ファイル | 案件.txt / 作業名.txt の読み書き（選択肢を作る読み取りと、画面編集用のモデル読み書き） |
| 4 | 日報CSV | 日次CSVの読み書き |
| 5 | 記録位置 | `$pendingStart`（次に記録すべき枠）の管理 |
| 6 | UI部品ファクトリ | フォント・スタイルを集約したコントロール生成、小さな入力・選択・確認ダイアログ |
| 7 | 機能テーブル | 機能ID → 表記と処理 |
| 8〜13 | 各ウィンドウ | 入力・休憩中・一覧編集・MTG予約・設定メンテナンス・日報メニュー |
| 14 | セルフテスト | `-TestInit` |
| 15 | 画面キャプチャ | `-Capture`。資料用のPNGを `画像\` に書き出す |
| 16 | メイン | 二重起動防止 → 業務開始ゲート → トレイ常駐 → メインループ |

### 機能テーブル（7章）

入力ウィンドウ・日報メニュー・タスクトレイという3つの入口が、同じ機能を別々に実装してズレるのを防ぐ仕組み。
`$FEATURES` に機能ID（`Edit` / `Reserve` / `Break` / `Maint` / `Close`）ごとの**表記と処理**を定義し、各入口は `Invoke-Feature 'Break'`、`Get-FeatureLabel 'Break'` で呼ぶだけにしている。**ボタンの文言も挙動も、変更はこのテーブル1か所で済む。**

### 設定メンテナンスウィンドウ（12章）

案件.txt / 作業名.txt を画面から編集する（機能ID `Maint`）。選択肢を作るための読み取り（`Read-ListFile` / `Read-TaskMap`）とは別に、**書き戻し用のモデル**（`Read-ProjectFileModel` / `Read-TaskFileModel` → `Write-*FileModel`）を持つ。ファイルを丸ごと作り直すため、冒頭の説明コメントと本文中のコメント行（無効化した項目のメモ）も保持して書き戻す（本文中のコメントは、そのセクションの末尾に寄せて残る）。

- 編集はメモリ上のモデルに対して行い、「保存して閉じる」で2ファイルを書き戻す。キャンセル・×では変更を確認のうえ破棄する
- 左の一覧の先頭「（共通）」は作業名.txtの見出しより前の行。案件.txtに無いのに作業名.txtに見出しだけ残っているセクションは、印つきで末尾に出す（画面に出ないと消せなくなるため）
- **過去の日報CSVには一切触らない。** 名前変更・削除で変わるのは次回からの選択肢だけ（記録は当時の表記のまま残す方針）。過去分の名寄せが要るときは一覧編集で直す

### 動作確認

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 日報記録\Nippo-Batch.ps1 -TestInit
```

ウィンドウを出さずに主要処理を検証し、JSONで結果を返す。**実データは変更しない**（一時フォルダにコピーして検証する）。
出力の `*Ok` がすべて `true` なら健全。検証内容は次のとおり。

| 項目 | 検証していること |
|---|---|
| `dedupOk` | 予約済みの枠と重なった記録を二重に書かないか |
| `gridSaveOk` | 一覧編集の保存で時刻順に並べ直されるか |
| `formatToleranceOk` | ExcelでCSVを保存して書式が変わっても読めて、書き直しで正規化されるか |
| `addToSectionOk` | 新しい作業名が選択中の案件セクションにだけ入るか |
| `maintSaveOk` | 設定メンテナンスの保存（案件の改名・作業名の追加）がファイルに反映され、コメント行が残るか |

`testWritten` / `testReadBack` / `testLastRow` は引用符・カンマ入りの値が書いて読み戻せることの確認。
`projectCount` / `taskCount` / `taskCountByProject` は実環境の現状表示。

## 実装上の注意

- **文字コードはUTF-8 BOM付きで保存すること。** BOMなしで保存すると日本語が化ける。
- 集合や配列を返す関数は `return ,$set` のようにカンマを付ける。付けないとPowerShellが中身を1件ずつに展開し、空のときは `$null` になる（過去に実際に踏んだ）。
- CSVの読み込みは表記ゆれに寛容にしてある（`$SLOT_PARSE_FMTS`）。Excelが `2026/8/7` や `9:15:00` に書き換えても読め、`Write-DayFile` で書き直したときに正規の書式へ戻る。
- 読めない行（手編集で壊れた行など）は、表示からは外すが**保存時にそのまま残す**。表に出ていない行を保存で消さないため。
- ウィンドウは起動時に1回だけ生成して使い回す。メモリ消費は常駐中ほぼ一定（100MB前後）。
- メインループは50msごとに `DoEvents` を呼んでトレイ操作に応答している。CPU使用率は1%未満。

## 紹介プレゼンの構成

全24枚。**本編13枚（何を作ったか）＋付録11枚（どう作ったか）**の2部構成。

| 範囲 | 章 | 内容 |
|---|---|---|
| 1〜13 | 本編 | 課題 → 発想 → 一日の流れ → 4つの画面 → CSV → 設定 → フォルダ構成 → 技術構成 → まとめ |
| 14〜17 | 付録A 作り方 | 役割分担 → 出発点（最初の2通）→ 進め方 → 実例 |
| 18〜20 | 付録B 評価 | AIから見た評価 → わかったこと → つまずきどころ |
| 21〜22 | 付録C 他のAIとの比較 | 比較表 → 境界線 |
| 23〜24 | 付録D 自己評価 | 使いこなしの段階 → 到達点 |

スライドの順番を変えたら、`aria-label="N/M タイトル"` の番号と直前のコメントを振り直すこと（出現順に自動で振り直すスクリプトを使うと安全）。ページ送りとルーラーはスライド数から自動計算されるのでJSの修正は不要。

マニュアルへのリンクはタイトルとまとめの2か所。**クリックするとダウンロードになる**（ブラウザの仕様）。

> **「クリックしたらExcelが直接開く」は実装を試みて断念した。** 再挑戦しないこと。
> ブラウザは安全のためローカルアプリを起動できず、唯一の抜け道である Office の `ms-excel:ofe|u|<パス>` プロトコルも、
> このフォルダのように**日本語を含むパスでは動かない**（ChromeがURLエンコードして渡すが、Excel側がデコードしないため
> `%E3%83%89…` を含むパスとして探しに行き「アクセスできません」になる。`file:///` 形式は「必要な情報をダウンロードできません」で失敗）。
> PowerShellの `Start-Process "ms-excel:ofe|u|C:\...\ユーザーマニュアル.xlsx"` は成功するので、
> **失敗しているのはブラウザからの受け渡し部分**であり、パスに日本語・空白が無ければ動く可能性はある。

## 紹介プレゼンのデザイン

`日報システム紹介プレゼン.html` の配色・書体は、**和文サイトの落ち着いたトンマナ**に合わせている。変更するときはこの方針を崩さないこと。

| 要素 | 方針（サイトから採用した値） |
|---|---|
| 背景 | 生成りの紙色 `#fdf8f6`（paper） |
| 文字 | 温かみのある黒 `#1a1a18`（ink） |
| 主色 | 臙脂 `#7a3a4a`（accent） |
| 差し色 | 桜 `#c0606a`（sakura-deep）／藍 `#3a6470`（accent-cool） |
| 罫線 | `#ddc8be`（paper-dark）を **0.5px** で。カードは左に2pxの桜色の縦線 |
| 見出し | Zen Old Mincho（明朝）・字間 0.06em |
| リード文・小見出し | Shippori Mincho |
| 本文 | Noto Sans JP・ウェイト300・行間1.8 |
| 角丸 | **使わない**（丸ポチとナビボタンのみ例外） |
| 影 | 紅を混ぜた淡い影 `0 10px 28px rgba(122,58,74,0.09)` |

色はすべてCSS変数（`:root`）にまとめてあるので、変更はそこだけで済む。ダークモードはサイトの `--surface-inverse` / `--inverse-ink` を基にした反転配色。
WebフォントはGoogle Fontsから読むため、**オフラインでは日本語の代替書体（游明朝・游ゴシック等）にフォールバック**する。指定は消さないこと。
